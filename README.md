# Samples of generation of rest server and client api components with OpenApi 

This is a multimodule maven project that includes samples to generate rest services 
based on a OpenApi V3 specification:

- *server-spring*: Rest server (Spring Boot 4, Jackson 3, Java 17)
- *client-resttemplate*: Java client api (Spring 7 and Jackson 3, Java 17)
- *client-httpclient*: Java client api (Apache Httpclient 5 and Jackson 3, Java 17)
- *client-netcore*: .NET Core client api (RestSharp and Newtonsosft.Json, net 6.0)
- *client-netstandard*: .NET Core client api (RestSharp and Newtonsosft.Json, netstandard 2.0)

## Running the server

From the project root, build the executable jar and run it:

```
mvn package -pl server-spring
java -jar server-spring/target/samples-openapi-server-spring-0.0.1-SNAPSHOT.jar
```

The api is then served at `localhost:8080` (eg. http://localhost:8080/pets), and the documentation
generated by SpringDoc is available at:

- Swagger UI: http://localhost:8080/swagger-ui/index.html (http://localhost:8080 redirects to it)
- OpenApi specification: http://localhost:8080/v3/api-docs and http://localhost:8080/v3/api-docs.yaml

## Notes
- To generate the api for all modules (including .NET Core) run `mvn generate-sources` from the project root
- The server is located in *server-spring* module at `giis.samples.openapi.invoker.OpenApiGeneratorApplication` or in an executable jar (if generated with `mvn package`)
- To run from Eclipse, ensure that the generated sources (`target/generated-sources/copenapi/src/main/java`) are included in the build path
- The .NET clients can be run from Visual Studio at `client-netcore/client-netcore.sln` and `client-netstandard/client-netstandard.sln`(each project is linked with the generated api code)
- The OpenApi schema is common for all modules, located at [schema/api.yml](schema/api.yml)
- The `/reset` endpoint restores the initial content of the pets store, all test suites invoke it in their setup to make tests independent
- Endpoints of services are `localhost:8080`
- Server is tested in a temurin java jre container

## Serialization of the optional properties that are not set

Each generator has its own convention to serialize the optional properties of a model
that are not set (eg. the `tag` of a pet):

- The models of the server omit them: since openapi-generator 7.24.0 the *spring* generator
  annotates the optional properties with `@JsonInclude(JsonInclude.Include.NON_NULL)`
  (in previous versions they were serialized as `null`)
- The models of the .NET client apis omit them too, they can be included by generating
  the api with the `optionalEmitDefaultValues` option
- The models of the java client apis include them as `null`

The test suites of all modules check this behaviour on both the json sent by the server
and the json obtained by serializing the models.
